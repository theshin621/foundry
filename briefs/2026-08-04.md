## RECOMMENDATION — ship 003 · `codeowners` (EVERGREEN lane)

**Paste your CODEOWNERS file and the files a PR touches. Get, per file, the exact rule that
won, who gets requested for review, and which rules lost — plus the lines GitHub silently
ignores.**

### Why this one

CODEOWNERS decides who is auto-requested on every pull request in most serious repos, and its
one binding rule is counter-intuitive: **"Order is important; the last matching pattern takes
the most precedence"** ([GitHub Docs, About code owners](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners)).
Not the most specific pattern — the *last* one. Three more documented footguns compound it:
`!` negation, `[ ]` character ranges, and `\#` escaping **do not work** in CODEOWNERS even
though the format is otherwise gitignore-shaped, and **"if any line in your CODEOWNERS file
contains invalid syntax, that line will be skipped"** — silently. The failure mode is a rule
you believe is protecting a directory that has quietly done nothing for months.

**Occupant hunt (named, 2026-08-04).** Everything that exists is a CLI or a library you must
install and run against a checkout:

| occupant | shape | why it isn't this |
|---|---|---|
| [hmarr/codeowners](https://github.com/hmarr/codeowners) | Go CLI + library (MIT) | install Go/brew, run in a repo; prints owners, not *why* |
| [mszostok/codeowners-validator](https://github.com/mszostok/codeowners-validator) | Go CLI | validates syntax + owner existence; does not resolve a file list |
| [orsinium-labs/owners](https://github.com/orsinium-labs/owners) | CLI | owned/unowned dirs, owners-for-path |
| [topfreegames/codeowners-verifier](https://github.com/topfreegames/codeowners-verifier) | binary | "does this path have an owner" |
| [nmusolino/codeowners](https://github.com/nmusolino/codeowners) | Python lib | library |
| [multimediallc/codeowners-plus](https://github.com/multimediallc/codeowners-plus) | GitHub Action | a replacement engine you install into CI, not a debugger |
| GitHub itself | web UI | flags syntax errors in the editor; **does not simulate a file list against the rules** |

No free, signup-free web page takes a pasted CODEOWNERS plus a list of changed paths and shows
which rule won per file and why. **The edge is structural, not inferential:** free vs
install-a-toolchain · paste vs checkout · whole changed-file list vs one path at a time ·
explains the precedence decision rather than printing a name · runs entirely in the browser, so
a private CODEOWNERS never leaves the machine (that last one is the real unlock — the audience
is exactly the people who cannot paste an internal ownership map into a hosted service).

**Promo-motive check:** the strongest write-up in the space
([dev.to "The definitive guide to CODEOWNERS… and why it's not enough"](https://dev.to/aleixriba/codeowners-4jn3))
reads as content marketing for a review-routing product — treated as a demand signal that the
pain is real and commercially interesting, not as evidence for any claim.

**Day-build gate:** static page, no credential, no runtime inference, no store review, no
account. Passes.

**BORROW-DON'T-BUILD — the risky core has a reference implementation, and it is already
cloned and building here.** The matcher is ported from
[`hmarr/codeowners`](https://github.com/hmarr/codeowners) (MIT, © 2020 Harry Marr) pinned at
`11d3ff2659b769bcb43ddef81a6ab19d1205d9c2` — `parse.go`'s rule/owner state machine and
`match.go`'s `buildPatternRegex` segment rules, line for line.

**THE TRAP, named before it bites (this is ship 002's lesson applied):** `hmarr/codeowners`
is linear-time *because Go's `regexp` is RE2*, not because its translation is safe.
`buildPatternRegex` emits ordinary regex text containing `(?:.+/)?`, `[^/]+`, `(?:/.+)?`. Ported
verbatim into JavaScript's **backtracking** `RegExp`, those shapes reintroduce exactly the
ReDoS that failed ship 002 twice. So: **semantics ported, execution replaced** — compile to a
Thompson NFA and run the Pike-VM state-set simulation already proven in `lib/gha-glob.js`, with
the same work-budget counter that measures work *done* rather than predicting blow-up.

**Day-VERIFIABLE, which is the other half of the gate.** Go 1.24.7 is in this sandbox and the
reference library's root package builds offline. A differential driver is already compiled and
answering:

```
$ echo '{"pairs":[["*.js","app/foo.js"],["apps/","x/apps/y/z"],["/apps/github","apps/github/a"]]}' | difftool
[true,true,true]
```

So the checker gets ground truth, not an argument: every (pattern, path) pair the JS matcher
answers can be re-answered by the real Go implementation and compared. Plus two published
oracles — the reference repo's own `testdata/patterns.json` (30 cases, 153 pattern/path pairs)
and GitHub's documented example block with its stated per-line expectations.

### Build order

- **Deploy target:** `public/003-codeowners/` on branch `ship/003-codeowners`, scaffolded from
  `lib/template.html` (beacon + footer kept).
- **Page:** two textareas — CODEOWNERS content, and changed paths (one per line) — plus a

  rules that match nothing in the given file list (dead rules). Prefilled with GitHub's own

- **Endpoints:** none. Entirely client-side; no network call but the cookieless beacon.

- **Distribution (non-ads):** hub entry; it sits beside `/002-gha-trigger/` as a second
