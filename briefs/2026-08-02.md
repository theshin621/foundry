**Root cause: the PAT is stored in the container filesystem, and scheduled runs get a fresh container.** `config.json` is written during an interactive wiring session and dies with that container. This is not a transient failure and it will not fix itself. It also explains the shape of the earlier zero-output runs: PLAYBOOK Amendment 4 makes "heartbeat, then push" the first action of every run, but a scheduled run in a fresh container **has no credential to push with**, so the survivability fix cannot execute. Ship 001 (2026-07-30) and the amendments commit (2026-08-01) both landed from sessions where the PAT was present in-context — not from a scheduled fire.

**Fix (Theshin, one of):**

1. **Put the PAT in the scheduled task's own prompt text** — the trigger prompt is the only thing that reliably survives into a fresh container. Costs: the token sits in the task definition. Mitigation: fine-grained, single-repo, Contents+PR write only, rotatable — the blast radius PLAYBOOK §8 already accepts.
2. **Re-create the loop as a local scheduled task on your machine** (Claude desktop → the task runs on your computer, where `config.json` persists on disk). This is the supported route for anything that needs local state, and it also restores the Chrome/live-URL verification path §5 wants.

Until one of those lands, **every subsequent run repeats this failure.** That is the lead item of this triage, ahead of anything about ships.

Second blocker: path filters were evaluated on tag pushes, which GitHub documents it never does. Plus an uncaught TypeError that left a stale green verdict across subsequent edits, a 300-vs-3,000 file-cap error, and `workflow_dispatch` filter keys reported as "silently ignored" when GitHub rejects the file outright.

**Fix cycle (one, per contract).** Glob rewritten (`**/`→`(.+/)?`, `?`/`+` as quantifiers, `\` escaping); tag pushes now skip path filters; `render()` wrapped so a throw paints an explicit TOOL ERROR instead of a stale verdict; copy corrected; `workflow_dispatch` unknown keys → INVALID WORKFLOW; ignore-lists honour `!`; `asList` rejects maps.

**Pass 2 — FAIL, on a defect the fix itself introduced.** The new YAML alias/anchor guard interpolates the raw user scalar into an exception message, and that message reaches `innerHTML` through the one `esc()`-free sink in the file (`why:e.message`). Pasting a workflow containing `- *<img src=x onerror=alert(1)>` executes attacker JavaScript on the page's origin — in a tool whose entire premise is "paste a workflow someone sent you". Confirmed firing four ways. Before the fix the sink was inert; the fix armed it.
