## PICKED — ship 002 rebuild: `gha-trigger`

**One-liner:** paste a GitHub Actions workflow and describe an event — get **WILL RUN /
WON'T RUN** and the exact filter that decided it.

### The failure being fixed, precisely

Ship 002's matcher compiled globs to a JS `RegExp`. JavaScript's regex engine backtracks,
so patterns like `****a****b****c****d` went exponential and froze the tab — synchronously,
so the `try/catch` never fired and a *stale verdict stayed on screen looking authoritative*.
The fix cycle added a complexity budget; the budget both (a) still let `*****a+a+a+a+Z` run
4.5 s and (b) broke a correct verdict on legitimate input. The checker's verdict was right:
**a static budget cannot bound this class. Only a non-backtracking matcher can.**

### BORROW-DON'T-BUILD — and the trap inside the borrow

Port target: `nektos/act` `pkg/workflowpattern` (MIT, cloned at `4f41128`, 2026-06-01).

**Critical finding from reading the source rather than trusting the plan:** act is safe
*not because of its pattern translation* but because Go's `regexp` is **RE2 — linear-time,
no backtracking**. Its `PatternToRegex` emits ordinary regex text. **A verbatim JS port
would reintroduce the exact ReDoS that killed ship 002**, because JS `RegExp` backtracks.

So the port splits in two:

* **Semantics — ported line-for-line from act** (`**/` → `(.+/)?`, `**` → `.*`, `*` →
  `[^/]*`, `+`/`?` postfix rules, `[...]` class validation, `\` escapes, `!` negation, and
  act's `Skip`/`Filter` set logic).
* **Execution — NOT JS `RegExp`.** A **Thompson NFA / Pike-VM state-set simulation**:
  O(len(value) × len(program)), no backtracking possible by construction. This is the
  "linear-time non-backtracking matcher" the rebuild constraint demands.

### Verification plan (day-buildable must mean day-verifiable)

Go 1.24.7 is present in the sandbox and act's source compiles. So a **real RE2-backed
reference binary** is built from act's own file and the JS matcher is diffed against it
over a large generated corpus — not a hand-written expectation table. Plus:

* `lib/checks/gha-filter-oracle.json` — GitHub's published cheat sheet (46 pairs), all must pass.
* **NEW, contributed back:** `lib/checks/act-workflowpattern-oracle.json` — all **64** cases
  extracted from act's own `workflow_pattern_test.go`, including `Skip`/`Filter` set results.
* `lib/checks/redos-probes.json` — every probe < 50 ms wall clock, no UI freeze.
* `lib/checks/xss-payloads.json` — including the thrown-`Error`-message sink that bit 002.

## CHECKER — verdict verbatim

Three independent checkers, none given a prior verdict, all on a different model from the
maker.

**Pass 1, primary:** *"VERDICT: PARTIAL — matcher is correct (0/56,766 divergences, 46/46,
64/64, 14/14 e2e), secure (0 XSS, no proto-pollution), private (1 request, 0
cookies/storage), and premises are docs-accurate, but the page's absolute printed claim 'No
input can make it hang' is false: a pasteable pattern/value pair produces a measured 5.6 s
synchronous tab freeze because the linear-time Pike VM is still O(pattern × value) with no
input-size guard."*

**Pass 1, independent security adversary:** *"VERDICT: FAIL — the freeze/hang objective
produced multiple reproduced, measured defects (up to a full tab crash and multi-ten-second
blocks well past the claimed 50ms ceiling), directly falsifying 'No input can make it hang,'
while the XSS objective found nothing across an exhaustive, corpus-plus-hundreds-more
sweep."* It measured 7,755 ms on 5,000 files × 100 patterns — and proved it was a true
event-loop freeze rather than merely slow work, by showing a screenshot fired 300 ms in
timed out without returning a frame at all and a 5 ms interval canary ticked **3** times
where ~1,358 were due. Also 12,889 ms on a 2,000-level nested YAML document containing no
glob patterns at all, >90 s unfinished on `'*?'`×20000, and a **tab crash** at 20,000 levels.

Both were right, and the finding is the interesting part: **linear time is not bounded
time.** The rebuild removed the exponential blow-up — the four named ReDoS probes went from
freezing the tab to 0.04 ms — but cost is still O(pattern × value), and the user pastes
both.

**Fix cycle (one, as the contract allows):** a work budget decremented by NFA states
*actually visited* and checked inside the loop. This is not the static budget that failed
ship 002 — that one tried to *predict*, from a pattern's shape, whether a backtracking
engine would explode, and an exponential cost function cannot be predicted, so a pattern
under the cap still hung. This counter measures work already done against a hard ceiling,
so it cannot be satisfied and exceeded at the same time. Out of budget yields **CANNOT
TELL**, never a verdict. Plus: encode each value once per evaluation rather than once per
pattern; cache the NFA scratch state on the compiled pattern; parser size/depth limits;
`.textLength` checked before `.value` (reading a 200 MB textarea costs ~3 s before parsing
even starts); clear the output *before* computing; 5,000-file and 4,096-character field
caps; and the printed claim narrowed to what was actually proven.

**Targeted re-check, fresh adversary on the fix diff:** *"VERDICT: PASS — every reported
defect is fixed and neither the cached NFA scratch state nor the shared work budget produced
any wrong verdict across ~69.5k RE2-differential and 6.1k bounded-vs-unbounded comparisons;
the only residuals are two low-severity, sub-second UX/copy nuances."*

| defect | before | after |
|---|---|---|
| 5,000 files × 100 patterns | 7,755 ms | **150 ms** (correct verdict, not a refusal) |
| 3,000-char `*` vs 40 KB path | 5,618 ms | **188 ms** → CANNOT TELL |
| `[a-z]+`×8000 | 9,675 ms | **238 ms** → CANNOT TELL |
| `*?`×20000 | >90 s unfinished | **194 ms** → CANNOT TELL |
| 2,000 / 20,000-level nested YAML | 12.9 s / **tab crash** | refused in **0 ms**, no crash |
| 20 MB ref vs 50 patterns | 4,578 ms | **0.9 ms** |

### Two residuals carried, not fixed — deliberately

The contract allows one fix cycle, and changing code after a verdict means staging something
unverified. Both are LOW and both are recorded verbatim in the ledger:

1. **`stale-verdict-repaint`** — `run()` is synchronous, so the `clear()` at its top is
   never painted before the compute; the browser shows the previous verdict as the last
   painted frame for up to ~0.67 s. DOM state is correct throughout, and a MutationObserver
   confirmed the old verdict is never re-inserted as current. Down from multi-second.
2. **`copy-latency-scope`** — the page's "about a fifth of a second" is scoped to matching
   work and matches the measured ~0.23 s budget, but pattern compilation and YAML parsing
   sit outside the budget, so worst-case *total* latency is ~667 ms — roughly 3× what a
   reader might infer. Not a false statement; an imprecise one.

Both are cheap next-session fixes: hop the compute onto a `requestAnimationFrame` so the
clear paints first, and either widen the budget to cover compilation or reword the sentence.
