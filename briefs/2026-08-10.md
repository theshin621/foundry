## 4. ARCHITECT — oracle before code, and the probe

`oracles/beacon-stats-relay/oracle.py`, written before a line of the artifact existed. It does not
inspect the numbers. The claim under test is not *are these plausible* but *did a machine outside
this sandbox actually measure them* — and those two are byte-indistinguishable in a file. So the
ground-truth channel is **api.github.com**: the run behind the numbers must exist, be *this*
workflow, at *this* commit. That call is this oracle's equivalent of BOTTLENECKS #1's "execute it in
a real browser" — observe the real system rather than predict it.

**PROBE-THE-ORACLE** (`probe.py`): 9 negative controls + 5 independent break attempts. The break that
shaped the design is **laundering** — a fire wanting to report unmeasured visits would not invent a
run id (one API call catches that); it would quote a *real* run id, of which there is one per push,
and attach any numbers it liked. `P6.workflow` and `P6.sha` exist because the probe constructed that
attack. The probe also caught a defect **in itself** on first run: control B4's expectation was
mis-specified, asserting an exit code where it meant to assert a predicate. Recorded rather than
quietly corrected — a probe that is not itself probed is decoration.
