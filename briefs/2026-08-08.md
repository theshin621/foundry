### Why this one, and why today

Yesterday's run ended with a named lesson and an honest warning. The lesson: *where a real
implementation exists, install it and diff against it — a maker's own oracle proves only that the
code agrees with the maker.* The warning: the two carry-over candidates (`dockerignore-sim`,
`rsync-filter-sim`) are the **same shape** as the thing that had just failed, and that shape has
now killed three of six ships.

`ssh-config-resolver` is the candidate that resolves the tension instead of ignoring it. It is the
same *user-facing* shape — a confusing precedence rule made visible — but a completely different
*verification* shape, because its reference implementation is `ssh -G`, which is:

| property | measured today, in this container |
|---|---|
| installable | `apt-get install openssh-client` → `OpenSSH_9.6p1 Ubuntu-3ubuntu13.18` |
| authoritative | it is not a port of OpenSSH's resolver; it **is** OpenSSH's resolver |
| cheap | one invocation is milliseconds — thousands of fuzz cases are affordable inside one run |
| total | `ssh -G` prints **every** effective option, so a diff catches errors of omission too |

Compare with what the last three failures had: ship 002 hand-rolled a glob engine; ship 003
hand-rolled CODEOWNERS with a maker-written oracle; ship 006 wrote a 43-case oracle where only 33
were checked against real `npm pack --dry-run`, and the 23/23 round-1 oracle was *still* wrong
about npm's most pervasive behaviour. Here there is no maker-written oracle at all. The oracle is
a binary, it disagrees loudly, and it can be asked ten thousand times before the checker ever sees
the page.

`dockerignore-sim` keeps its #2 rank on demand, but drops below this on that one axis: its
reference implementation (`moby/patternmatcher`) is Go, so standing its oracle up costs a Go
toolchain first. Today's pick is the one whose oracle was *already running* before the brief was
written.

### The gaps this fills (why-now waived — EVERGREEN lane)

No news hook is claimed. The demand is permanent and structural: OpenSSH's config file is
**first-obtained-value-wins**, which is the opposite of what almost everyone assumes (most people
read it as last-wins, or as "the most specific block wins"). Combined with `Host *` blocks that
people put at the top of the file, and `Match` blocks whose criteria are evaluated against values
that earlier blocks may already have changed, the result is a file where the answer to "which
`User` will I actually connect as?" is genuinely hard to read off the page.

`ssh -G` answers it — but only if you are on a machine with that config, only for one host at a
time, and it tells you the *value* while saying nothing about **which line produced it** or which
of your blocks were considered and rejected. That last part is the product.

### BUILD ORDER

**Deploy target:** `public/007-ssh-config-resolver/` on branch `ship/007-ssh-config-resolver`.

**Page (one file, self-contained, assembled by `lib/inline.js` so the inlined copy is provably
identical to `lib/`):**

1. Two inputs — a textarea for the config, and a single line for the target (`user@host` accepted,
   `-l user` semantics). Both bounded at the door by `lib/door.js` **before** any split or parse
   (total chars, non-blank lines, total segments, line length, field length — the two-line-caps
   rule from 2026-08-06).
2. Output panel A — **effective options**, the supported keyword subset, each with the value and
   the **1-indexed line number** that set it, plus the shadowed later lines that lost to
   first-wins (this is the half `ssh -G` does not give you).
3. Output panel B — **block trace**: every `Host`/`Match` block in file order, matched or not, with
   the specific reason (which pattern matched, which negation vetoed it, which criterion failed).
4. Every HTML-from-input sink routes through `lib/esc.js`; no raw `innerHTML=` anywhere (the
   checker greps for it).

**Scope, declared explicitly and refused loudly rather than silently mis-answered** — the ship-006
lesson was that a silent wrong answer is worse than a stated limit:

- Supported `Match` criteria: `all`, `host`, `originalhost`, `user`, `localuser`.
- **Refused with a named message, not ignored:** `Match exec` (cannot execute), `Include` (no
  filesystem), `Match final` / `Match canonical` (require OpenSSH's second resolution pass),
  percent-token expansion (`%h`, `%p`, `%r`). If a config uses one of these, the page says so and
  declines to give an effective-value verdict for the affected keywords.
- Pattern matching (`*`, `?`, `!`, comma/space lists) executes on **`lib/nfa.js`**, the existing
  linear-time matcher core — no new regex, no backtracking class, no ReDoS surface.
- The `Match host`/`user` subtlety is in scope and must be handled, not waived: OpenSSH evaluates
  a `Match` criterion against the **current** value of hostname/user at that point in the file, so
  an earlier `Hostname`/`User` line changes what a later `Match` sees.

**Verification corpus (this is the ship's centre of gravity, not an afterthought):**

- `lib/checks/ssh-config-oracle.json` — cases generated from a grammar over the supported subset,
  each one run through **real `ssh -G -F <cfg> [-l user] <host>`** on OpenSSH 9.6p1 and stored
  with its actual output. Handwritten cases are allowed *in addition to* the fuzz corpus and never
  *instead of* it.
- A fuzz harness that diffs our resolver against `ssh -G` across thousands of generated configs.
  **Zero mismatches on the supported keyword subset is the bar**; any mismatch is a defect, not a
  "difference of interpretation".

**lib/ contribution back:** `lib/sshconfig.js` — OpenSSH client-config parser + first-wins resolver,
executing its pattern matching on `lib/nfa.js`.

**Analytics events:** none beyond the standard cookieless pageview beacon already in
`lib/template.html`. Cloudflare's free tier has no custom events; pretending otherwise is what
amendment 2026-08-02b clause 5 exists to prevent.

**Merge hygiene (amendment 2026-08-02 clause 9):** the branch touches only
