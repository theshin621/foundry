### The gaps this fills (why-now waived — EVERGREEN lane)

No news hook is claimed. The demand is permanent and structural: OpenSSH's config file is
**first-obtained-value-wins**, which is the opposite of what almost everyone assumes (most people
read it as last-wins, or as "the most specific block wins"). Combined with `Host *` blocks that
people put at the top of the file, and `Match` blocks whose criteria are evaluated against values
that earlier blocks may already have changed, the result is a file where the answer to "which
`User` will I actually connect as?" is genuinely hard to read off the page.

`ssh -G` answers it — but only if you are on a machine with that config, only for one host at a
time, and it tells you the *value* while saying nothing about **which line produced it** or which
of your blocks were considered and rejected. That last part is the product.

### The method, which outlived the ship

Yesterday's rule was *diff against the real implementation.* Today found the shape that makes it
bite hardest, and it is worth stealing for every future ship whose reference implementation is a
**program** rather than a library.

A per-keyword diff — "for each option I claim, does the real tool agree?" — only tests what the
maker thought to ask about. It cannot see an option you **dropped**, because you never asked.
Ship 006 died of exactly that.

**Replay closes it.** Take the answer, write it back out as a minimal input to the reference
implementation, run the reference implementation on *that*, and require its **entire** output to
be identical to its output on the user's original input:

```
ssh -G -F <the user's config> <host>   ==   ssh -G -F <our resolved answer> <host>
```

All ~80 options ssh prints are compared, including the ones nobody enumerated. It also reproduces
the reference implementation's internal side-effects for free — OpenSSH derives
`ServerAliveInterval 300` from `BatchMode yes`, and a naive baseline diff flags that as a defect,
while the replay gets it right on both sides and stays quiet. Hand-maintaining a table of those
side-effects would have been a maker's-own-oracle in disguise.

**It found four real defects before any checker saw the page**, three of them unreachable from the
documentation:

1. a command-line user (`ssh -l u host`) outranks **every** `User` line in the file, and `Match user`
   keeps seeing the command-line user no matter what a `User` line above it says;
2. five of the six accumulating keywords **de-duplicate** identical values, globally rather than
   adjacently — `sendenv` alone does not;
3. `ProxyCommand`, `LocalCommand`, `RemoteCommand` and `KnownHostsCommand` take the **rest of the
   line raw**, so a `#` inside them is part of the command and not a comment;
4. `Match user` was being evaluated against the wrong subject.

The keyword table was derived the same way and is worth recording as a technique: extract every
lowercase token **and every suffix of every token** from `/usr/bin/ssh` — the linker tail-merges
short string literals, which is why a naive `strings` pass silently loses `host`, `user`, `port`
and `match` — then feed all 3,436 candidates to the real binary one at a time and keep the ones
that do not produce "Bad configuration option". 134 survived; two of them were suffix-only
candidates the first pass had missed, which is the evidence that the suffix expansion was
necessary rather than paranoid.

4. **`Match tagged` manufactures doubt it cannot have** — the page can never supply an `ssh -P`
