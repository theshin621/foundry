### Why a SHIP today, when a ship cannot merge without Theshin

This needs saying plainly, because yesterday's fire reasoned the other way and the record
now judges that reasoning. On 2026-08-13 the brief picked infra explicitly because
*"it is the only thing that can publish today"* — ship merges being gated, infra merges
autonomous. That is optimising the **pick** for **mergeability** instead of for value, and
it has now been run three times: **#009, #013 and #014 were all infra, and all three
FAILED.** Worse, all three failed the same way — the loop verifying itself, with the defects
climbing from the product into the oracle into the oracle's own fixtures. #014's finding was
that *"the fix whose entire purpose was to eliminate decorative verification shipped a
decorative control of its own."* That is what recursion looks like from the inside.

Staging-and-waiting is not a reason to build the wrong thing. A staged ship that is right
costs Theshin one word; three merged instruments that are wrong cost the ledger its
credibility. **Building a product instead of an instrument removes the recursion entirely** —
the oracle is no longer auditing a thing whose job is auditing.

### Why the oracle story is the best available, and unprecedented here

Every failed build in this entry's history was checked against **predicates the maker
authored**. The ARCHITECT contract's *preferred* oracle forms are "reference implementation,
real dataset" — and in fifteen days **the loop has never once used either.** This pick
offers both: **`pass-import` is a real, mature reference implementation with a published test
corpus of real export files.** The oracle can be differential — for each fixture, does the
page produce what the reference produces — which is a target set the maker cannot quietly
redefine mid-cycle. That is the specific mechanism BOTTLENECKS #1 keeps asking for.

### The tail is closed by construction, and that is the whole design

Entry #1's diagnosis is that long-tailed scope lets each fix reveal the next rule. So the
scope is fixed before the first line and is deliberately **small**:

**Exactly four source formats — Chrome/Chromium, Bitwarden, LastPass, 1Password — and
exactly one destination, Bitwarden.** Everything else is **refused by name** with the
detected header echoed back and a plain "this tool does not handle *x*". **A refusal is a
correct output, not a missing feature.** An unbounded format list is the defect; a bounded
one with an honest refusal is the fix. If the checker finds a fifth format mishandled, the
answer is a better refusal, never a fifth parser.

### Build order

1. **ARCHITECT — `oracles/015-password-csv-remapper/`, before any product code.** Real
   dataset: fixture CSVs for the four supported formats plus adversarial ones (empty file,
   header only, BOM, CRLF, quoted commas and embedded newlines in a password field, an
   unsupported fifth format, a 5 MB file). Differential predicates against the reference
   where it applies; explicit expected refusals where it does not.
2. **PROBE-THE-ORACLE (mandatory, both clauses).** (a) Negative control — break the parser
   deliberately (drop a column, mis-order the mapping, swallow a quoted comma) and confirm
   each goes RED. (b) Independent attempt to construct a page the oracle passes while being
   wrong. **Liveness-of-markup claims execute the page in Chromium** — no hand-written
   parse-and-match walker, per entry #1's third clause and its five incidents.
3. **BUILDER — `ship/015-password-csv-remapper` from `lib/template.html`.** Borrow-don't-build
   the CSV parsing: a real parser, ported with attribution, never hand-rolled — and keep the
   hand-written band around it minimal and oracle-covered, because *"a borrowed primitive
   does not make the caller correct"* is this entry's most expensive lesson. `esc()` on all
   HTML-from-input. No upload, no network, no storage.
4. **CHECKER — independent subagent, different model,** driven cold against the architect's
   oracle, `public/` served locally, real-browser execution for the liveness claim.

**Deliberately NOT attempted:** a third round on `infra/014-beacon-liveness-oracle` or
`infra/013-stats-window-floor`. Both have two independent FAILs and rising severe counts; a
third round on the same artifact is precisely the grinding the anti-grind clause exists to
