### 1. `npm-publish-preflight` — EVERGREEN — **RECOMMENDED**

**What:** paste your `package.json`, your `.npmignore`/`.gitignore` and your file list; see the
exact set of files `npm publish` will put in the tarball, and for every file the *one rule that
decided it* — which source, which pattern, which line.

**Why it exists:** the precedence between `files[]`, `.npmignore`, `.gitignore` and npm's own
always-in/always-out lists is genuinely confusing, and the failure is silent and public: people
ship `.env` and `node_modules`, or publish a package with `dist/` missing, and only find out
after the version is immutable on the registry.

**Occupant hunt — run fresh today, three searches, empty at the web-tool layer.** What exists is
documentation and CLI: npm's own docs, the npm/cli *Files & Ignores* wiki, npm's 2017
"Publishing what you mean to publish" post, the "don't use .npmignore" essay, and CLI-only
workarounds (`npm pack --dry-run`, `pure-publish`, the `npmignore` package). No page takes the
four inputs and shows you the resolved set with per-file reasons. `npm pack --dry-run` is the
closest thing and it (a) needs the project checked out locally, (b) gives you a file list with
no *why*, and (c) is exactly the step people skip.

**Structural edge:** whole-resolution vs one-rule, and *reasons* vs a bare list. No signup, no
install, nothing leaves the browser — which matters, because the input is your private tree.

**Promo motive:** none. No vendor benefits from me believing this; the sources are npm's own docs
and a nine-year-old complaint thread.

**Day-build gate: PASS.** Static page, no API key, no account, no marketplace, no review.
Borrow-don't-build satisfied twice over: the *semantics* are published rules (three citations
below) and the *matcher* already exists in this repo — `lib/nfa.js`, proven linear-time.

**Rules pinned to primary sources (the checker re-verifies these, not my memory):**

- Always included, any case/extension: `package.json`, `README`, `LICENSE`/`LICENCE`, the file
  in `main`, the file(s) in `bin`.
  — <https://docs.npmjs.com/cli/v11/configuring-npm/package-json>
- Always ignored: `*.orig`, `.*.swp`, `.DS_Store`, `._*`, `.git`, `.hg`, `.lock-wscript`,
  `.npmrc`, `.svn`, `.wafpickle-N`, `CVS`, `config.gypi`, `node_modules`, `npm-debug.log`,
  `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lockb`.
  Of those, a hard core **cannot be re-included even if named explicitly**: `.git`, `.npmrc`,
  `node_modules`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lockb`.
  — same page.
- `.npmignore` **replaces** `.gitignore`, it does not merge with it: "If there is a `.gitignore`
  file, and `.npmignore` is missing, `.gitignore`'s contents will be used *instead*." An **empty**
  `.npmignore` therefore turns `.gitignore` off entirely.
  — <https://docs.npmjs.com/cli/v11/using-npm/developers/> and
    <https://github.com/npm/cli/wiki/Files-&-Ignores>
- `files[]` is an allowlist and currently **wins over** `.npmignore`: "Entries matched by `files`
  will be included, regardless of `.npmignore` settings" — flagged in npm's own wiki as a known
  issue (#11669) rather than intended design. The page states this *and* labels it as npm's open
  bug, because a tool that quietly picks the "right" answer over the shipped one is lying.
  — <https://github.com/npm/cli/wiki/Files-&-Ignores>

### Checker A — semantics and premise (verbatim)

> VERDICT: FAIL
>
> Confirmed against real npm (installed npm 11.19.0 / npm-packlist 10.0.4, verified current via `npm pack --dry-run --json` in scratch fixtures under /tmp/npmcheck, then reproduced live in Chromium at http://127.0.0.1:8006/006-npm-publish-preflight/):
>
> 1. **Backslash-in-filename: verdict flip + fabricated reason.** File `weird\file.js` (literal backslash, valid on Linux) plus `.npmignore` rule `weird/` plus a real `weird/real.js`. Real npm ships `weird\file.js` (single top-level file, untouched) and excludes `weird/real.js`. The page excludes **both**, displaying the first as `weird/file.js` and citing `.npmignore weird/ line 1 — "the directory 'weird' is excluded"` — a directory that does not exist. Root cause: `lib/npmpack.js` `norm()` does `.replace(/\\/g,'/')` unconditionally, so it path-mangles the identity of the file *and* invents the reason. This falsifies both halves of the product's claim on one input.
>
> 2. **Case-insensitivity, systemic.** Real npm's matcher (`ignore-walk/lib/index.js:108`, `nocase: true`, hardcoded, unconditional) matches every rule case-insensitively — defaults, hard-excludes, and user's own `.npmignore`/`.gitignore` lines alike. `lib/gitignore.js` is case-sensitive throughout. Confirmed live: `NODE_MODULES/dep/i.js` and `Node_Modules/dep/i.js` → page says PUBLISHED, real npm excludes both. User rule `*.log` + `dist/` → page publishes `DEBUG.LOG` and `Dist/inside.js`; real npm excludes both.
>
> 3. **`files[]` loses its anchor on `./` or `/`.** `files:["./dist"]` and `files:["/dist"]` should anchor to the package root (real npm: `file.startsWith('./')` → strips only the dot, keeps `/`). `norm()` strips both entirely. With `dist/a.js` + `sub/dist/b.js`: real npm ships only `dist/a.js`; page also ships `sub/dist/b.js`.
>
> 4. **`files` as a non-array string.** `files:"dist"` (plausible typo): real npm iterates the string char-by-char, effectively publishing almost nothing (`package.json`+`README.md` only). The page's `Array.isArray` guard fails silently and treats it as no `files` field at all, publishing everything (`dist/a.js`, `index.js` too) — the opposite outcome.
>
> 5. **`browser` field never force-included.** Real npm (`strict.push('!/${browser}')`) force-includes it like `main`/`bin`, even outside `files[]`. `lib/npmpack.js` never reads `pkg.browser`.
>
> Tried and did NOT break: last-rule-wins + line numbers across comments/blanks (exact); char classes `[!a-z]`, `[]]`, `[a-]`, unterminated `[` (all correct, matched real npm); README/LICENSE case+extension+root-only depth; `main`/`bin` incl. `./` prefix on `main` itself and object-form `bin`; `files:[]` empty array; `.npmignore` replace-not-merge incl. empty-present; the disclosed "defaults still apply inside files[] dir" guess (confirmed right); build reproducibility (`page.src.html`→`index.html` byte-identical via `lib/inline.js`).
