## 3 — ARCHITECT (oracle before code, per v4)

**Nothing was built until this section was finished.** `oracles/012-chat-export-redactor/`
contains, authored against a page that did not yet exist:

- **`manifest.json`** — the page contract (DOM ids, the pure API `window.ChatRedact.redact`), five
  fixtures with a per-fixture identifier manifest, and ten named predicates. Fixing the DOM contract
  before the build is the point: an oracle shaped around whatever the builder happened to produce is
  an echo, not a test.
- **`oracle.py`** — drives Chromium via Playwright. Loads the page, sets the real file input, waits
  on the page's own completion flag (never a fixed sleep), **captures the actual download streams**,
  and judges those. Ten predicates: P1 client-side (network interception) · P2 zero residual
  identifiers · P3 bijective mapping · P4 line-count and verbatim-timestamp preservation ·
  P5 determinism across two independent browser contexts · P6 non-destruction · P7 Telegram output
  still valid JSON · P8 no mapping leak into the sanitised file · P9 XSS inert **in the engine** ·
  P10 garbage input reaches an ERROR state and is offered no download.
- **`probe.py`** — ten negative controls plus Part B.

**Why a browser and not a parser.** BOTTLENECKS #1 clause 3 is binding here and it is not
ceremony. Every claim this ship makes is behavioural: *"the file never leaves your machine"* is a
claim about network traffic, and *"the payload does not run"* is a claim about a JS engine. A static
walker can be green on a page a browser proves broken — that is precisely how #008 failed four
times. So P1 watches requests and P9 reads `window.__pwned` after execution.

**question → delete → simplify → accelerate → automate, run on the requirements.**

- *Deleted:* `.zip` ingestion (WhatsApp's zip contains the same `.txt` plus media; media redaction is
  a different, much larger product and pretending otherwise is how a day-build becomes a week).
  Deleted: any server, any account, any settings panel.
- *Simplified — this is the significant one.* The obvious design parses the chat into records and
  re-serialises them. That design **cannot** preserve timestamps byte-identically and puts the whole
  locale zoo (day-first inference, AM/PM, RTL marks, multi-line messages) inside the hand-written
  band, which is exactly where BOTTLENECKS #1 says the defects now live. So: **parse only to learn
  WHO is in the file, then redact by substitution over the original bytes.** Structure preservation
  becomes true by construction rather than by test, and the hand-written band shrinks to
  "collect identifiers, substitute them".
- *Borrowed, not built (Amendment 2026-08-02b.2 — binding):* the locale-aware header/author parser is
  `whatsapp-chat-parser@4.0.2` (Loris Bettazza, **MIT**, `npm pack`ed and inlined verbatim, 3.1 KB,
  attributed in-page and in `lib/`). This is the exact shape of core the rule names — a matcher with
  a long tail of formats — and it is the shape that killed ships 003, 006 and 007. The reference
  implementation existed; hand-rolling it would have been a choice to repeat the mistake.
  **And the rule's own limit, from BOTTLENECKS #1's most recent lesson:** *a borrowed primitive does
  not make the caller correct.* The band around it is kept to protect-and-restore of the timestamp
  prefixes plus word-boundary substitution, and every line of that band is under a predicate.

**Oracle: 40/40 green. Probe: 10/10 negative controls caught.**

**The oracle earned its keep before the checker ever saw the page — twice.**

1. *Blob downloads are refused on `file://`.* The first oracle run loaded the page from disk and
   timed out waiting for a download. The tempting repair was to read the DOM instead. That would
   have certified a code path **no visitor ever runs**. The oracle now serves `public/` over
   `http://127.0.0.1` and judges the real download stream — which is also what the checker contract
   already required, arrived at from the other direction.
2. *A CSS specificity bug left the download link live on a rejected file.* `a.btn` is (0,1,1) and
   `.hide` is (0,1,0), so `display:none` lost. The page cheerfully offered a "sanitised" download of
   a file it had just refused to parse — **the single worst failure this product can have**, and
   invisible to any check that reads markup rather than computed style. P10 caught it in the first
   full run. Fixed with `!important` and a comment explaining that the `!important` is load-bearing.

Both are exactly the failure shape BOTTLENECKS #1 clause 3 exists for: markup present, browser
disagrees. Neither would have been found by a parse-and-match walker.

**FIX CYCLE — one, as permitted.** The two SEVEREs (1) and (2) are one root cause: *the identifier
set was collected only from author fields.* They were repaired **structurally rather than
case-by-case**, because a file full of one-line patches is precisely what BOTTLENECKS #1 is:

- WhatsApp: a table of the closed, WhatsApp-generated system-line grammar. Documented limit,
  now printed on the page itself: **English-locale exports only.**
- Telegram: the fix is deliberately *not* "also read `members`". It is a **recursive walk of the
  whole document collecting by key name**, so a future export that puts a name in a new container
  is covered by construction.
- Findings (3) and (4) are also one cause — matching name *literals*. The repair stops doing that:
  fold to base letters, expand each into its variant class, match case-insensitively.
- (5) a bare-domain rule; (6) scheme-URLs now redact before emails.

The fix immediately produced its own small regression — a 40-character cap meant to stop system-line
patterns over-capturing a subject line silently **dropped a legitimate long author name**. The oracle
caught it in one run. The cap now applies only to system-line captures.

Two **checker-derived** fixtures were added to the oracle so the repairs are held by a predicate

### The finding that matters more than the ship

The oracle-first rule was followed to the letter. Probe-the-oracle passed 10/10. **And the oracle
went 40/40 green on a page with three SEVERE defects in it.** The round-1 checker diagnosed exactly
why, and the sentence deserves to be the day's headline:

> *the oracle compares residual identifiers case-insensitively, so this defect would have been
> caught immediately had any of the five architect fixtures included a differently-cased mention —
> none do, which is why 40/40 stayed green.*

An oracle fixes the target set **to what its author already knew how to handle**. Probe-the-oracle
proves the oracle can go RED; it does not prove the oracle is looking in the right places. Both are
necessary and neither is sufficient.

**Proposal for Theshin, offered by the party it constrains:** *the checker's first act should be to
write fixtures, not to run the oracle.* The adversary's cases enter the instrument **before** the
verdict is taken, instead of living only in a review nobody re-runs. Evidence it would have worked
here: two of this ship's three rounds were spent discovering cases an adversary contributed in
minutes once asked, and the round-2 adversary went straight to the oracle's blind spot unprompted.
The cost is one extra step before each verdict. The risk is that the checker starts co-owning the
target set and loses independence — which is the objection, stated because it is real.
