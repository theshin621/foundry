## 3 — ARCHITECT (oracle before code, per v4)

**Nothing was built until this section was finished.** `oracles/012-chat-export-redactor/`
contains, authored against a page that did not yet exist:

- **`manifest.json`** — the page contract (DOM ids, the pure API `window.ChatRedact.redact`), five
  fixtures with a per-fixture identifier manifest, and ten named predicates. Fixing the DOM contract
  before the build is the point: an oracle shaped around whatever the builder happened to produce is
  an echo, not a test.
- **`oracle.py`** — drives Chromium via Playwright. Loads the page, sets the real file input, waits
  on the page's own completion flag (never a fixed sleep), **captures the actual download streams**,
  and judges those. Ten predicates: P1 client-side (network interception) · P2 zero residual
  identifiers · P3 bijective mapping · P4 line-count and verbatim-timestamp preservation ·
  P5 determinism across two independent browser contexts · P6 non-destruction · P7 Telegram output
  still valid JSON · P8 no mapping leak into the sanitised file · P9 XSS inert **in the engine** ·
  P10 garbage input reaches an ERROR state and is offered no download.
- **`probe.py`** — ten negative controls plus Part B.

**Why a browser and not a parser.** BOTTLENECKS #1 clause 3 is binding here and it is not
ceremony. Every claim this ship makes is behavioural: *"the file never leaves your machine"* is a
claim about network traffic, and *"the payload does not run"* is a claim about a JS engine. A static
walker can be green on a page a browser proves broken — that is precisely how #008 failed four
times. So P1 watches requests and P9 reads `window.__pwned` after execution.

**question → delete → simplify → accelerate → automate, run on the requirements.**

- *Deleted:* `.zip` ingestion (WhatsApp's zip contains the same `.txt` plus media; media redaction is
  a different, much larger product and pretending otherwise is how a day-build becomes a week).
  Deleted: any server, any account, any settings panel.
- *Simplified — this is the significant one.* The obvious design parses the chat into records and
  re-serialises them. That design **cannot** preserve timestamps byte-identically and puts the whole
  locale zoo (day-first inference, AM/PM, RTL marks, multi-line messages) inside the hand-written
  band, which is exactly where BOTTLENECKS #1 says the defects now live. So: **parse only to learn
  WHO is in the file, then redact by substitution over the original bytes.** Structure preservation
  becomes true by construction rather than by test, and the hand-written band shrinks to
  "collect identifiers, substitute them".
- *Borrowed, not built (Amendment 2026-08-02b.2 — binding):* the locale-aware header/author parser is
  `whatsapp-chat-parser@4.0.2` (Loris Bettazza, **MIT**, `npm pack`ed and inlined verbatim, 3.1 KB,
  attributed in-page and in `lib/`). This is the exact shape of core the rule names — a matcher with
  a long tail of formats — and it is the shape that killed ships 003, 006 and 007. The reference
  implementation existed; hand-rolling it would have been a choice to repeat the mistake.
  **And the rule's own limit, from BOTTLENECKS #1's most recent lesson:** *a borrowed primitive does
  not make the caller correct.* The band around it is kept to protect-and-restore of the timestamp
  prefixes plus word-boundary substitution, and every line of that band is under a predicate.
