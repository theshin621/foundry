# oracle — ship 015 `password-csv-remapper`

Written **before any product code existed**, per PLAYBOOK v4 (oracle-before-code) and
BOTTLENECKS #1's shipped fix. Run it:

```sh
python3 make_fixtures.py                      # regenerate the corpus (committed)
python3 oracle.py path/to/index.html          # PASS / FAIL / CANNOT-CERTIFY
python3 probe.py                              # probe-the-oracle, all clauses
```

Exit codes: oracle `0=PASS 1=FAIL 2=CANNOT-CERTIFY`; probe `0=survived 1=not trustworthy`.

## Why this oracle is shaped differently from the six before it

BOTTLENECKS #1 is at count 5 (+5 unadjudicated) and every incident shares one mechanism:
**the artifact was checked against predicates the maker authored**, so each fix cycle
revealed the next rule the maker had not thought of. The defects climbed from the product
(#006, #007) into the oracle (#013) and then into the oracle's own fixtures (#014).

This oracle does not author the correctness criterion. **`pass_import` does, and it sits on
both ends of the comparison:**

```
fixture bytes ─[pass_import.ChromeCSV|BitwardenCSV|LastpassCSV|OnePassword8CSV]→ REFERENCE records
fixture bytes ─[the page, executing in real Chromium]→ output CSV
               ─[pass_import.BitwardenCSV]───────────→ ACTUAL records
PASS iff REFERENCE == ACTUAL  (multisets, compared per non-empty field)
```

`pass_import` is a mature third-party importer whose column mappings *are* the spec for
these four formats. The maker cannot quietly redefine the target set mid-fix-cycle,
because the target set is computed by a library the maker does not control. In fifteen
days the loop had never used a reference implementation or a real dataset, despite both
being the ARCHITECT contract's preferred oracle forms.

**The page is executed, never parsed.** Entry #1 clause 3 forbids hand-written
parse-and-match walkers for behaviour claims. There is no markup inspection in `oracle.py`:
Chromium loads the page, real bytes go to a real file input, the DOM is read after.
No browser ⇒ `CANNOT-CERTIFY`, never `PASS` — a missing tool must not read as a blessing.

**Scope is closed by construction.** Four source formats, one destination, everything else
refused **by name**. A refusal is a correct output, and five fixtures assert it. If a
checker finds a fifth format mishandled, the answer is a better refusal message, never a
fifth parser. This is the direct countermeasure to entry #1's open question #2, which
names "port a long-tailed reference implementation's semantics" as the common ancestor of
ships 006, 007 and 012.

## The corpus

13 fixtures, generated by `make_fixtures.py` so the exact bytes are inspectable in code
rather than rotting in an editor. 7 `convert` · 1 `empty` · 5 `refuse`.

Every format fixture carries the same nine adversarial rows: quoted comma + escaped quote
in a password, embedded newline, unicode + NBSP, leading/trailing whitespace that must be
preserved verbatim, an empty password (a real row, not a skip), semicolons that must not
become delimiters, formula-injection shapes that must stay literal text, and — added by
PROBE FINDING 6 — two rows with genuinely **empty** optional fields. Byte-level variants
(CRLF, UTF-8 BOM) carry identical logical content, so "it worked on my file" cannot pass.

## PROBE-THE-ORACLE: what attacking it actually found

Both mandatory clauses ran, plus two this incident added. **The probe found seven real
defects, all of them before a single line of product code existed.** That is the whole
argument for oracle-before-code, and it is the first time in this loop's history that an
oracle's defects were found by probing rather than by a checker after the build.

| # | finding | severity |
|---|---|---|
| 1 | **A failure *message* destroyed a verdict.** `P9`'s detail string called the reference parser a second time, and Python evaluates `%`-format arguments eagerly — so it ran even when the condition short-circuited past it. `BitwardenCSV.parse('')` raises `TypeError` (`csv.DictReader` leaves `fieldnames` None; `checkheader` does `in None`). Result: **67/67 predicates green, then `CANNOT-CERTIFY`.** | severe |
| 2 | **One fixture raising aborted the whole run.** Any exception anywhere returned `CANNOT-CERTIFY` for everything, so **10 of 11 negative controls came back `CANNOT-CERTIFY` instead of `FAIL`** — the probe could not distinguish "the oracle caught this" from "the oracle fell over", and a weaker probe would have counted those reds as catches. Fixed structurally: a fixture that explodes is a named `FAIL` of that fixture; `CANNOT-CERTIFY` is now reserved for "could not run at all". | severe |
| 3 | **A mutation silently no-opped.** `never_settles` anchors in the page shell, but `build_page` searched only the core — so the probe reported it as applied while testing nothing. A probe that cannot apply its own mutation must say so. | severe |
| 4 | `P11.parses` and `P2.noerror` were **decoration**: no control isolated them. Two controls added. | medium |
| 5 | **A control that passed for the wrong reason** — `b4_reverse_order` injected `out.reverse()` at module scope where `out` does not exist, so it threw, was "caught" by `P2`/`P3`, and looked like a working control while never testing order. **#014's exact defect, reproduced by this probe's own author.** | medium |
| 6 | **A fixture gap hid a whole defect class.** `b1_inject_extra_field` — invent a `notes` value into rows that have none — **PASSED**, not because the oracle was tolerant but because *every fixture row had a non-empty notes field*, so the mutation never executed. Two sparse rows added; it now fails on three fixtures. | severe |
| 7 | `P4.refuse_noout`, `P6.refuse_zero`, `P9.empty_noout` were decoration. Three controls added, each built to trip **exactly one** of them with `data-state` left correct, so `P3.state` cannot take the credit and leave the target unisolated. | medium |

Final state:

```
positive control GREEN, and green for the right reason (clause d)
16/16 negative controls caught (clause a)
no predicate family is decoration (clause c) — only P0.* self-checks idle, by design
5 break attempts, none succeeded (clause b)
```

### Clauses

- **(a) negative control** — 16 mutations, each a defect this page could plausibly ship,
  applied *textually to `lib/pwcsv-remap.js`* so the break is in the code under test and
  not in the harness. A mutation whose anchor is missing is a probe failure, not a skip.
- **(b) independent break attempt** — 5 attempts to pass the oracle while being wrong.
  One (`b1`) succeeded on the first run and produced finding 6.
- **(c) no predicate is decoration** — #014's lesson. Every predicate family must be the
  thing that catches some negative control. Idle predicates are named, not excused.
- **(d) the positive control passes for the RIGHT reason** — #014's *other* lesson, the one
  clause (c) cannot catch: a decorative fixture still flips a verdict, just for the wrong
  reason. So the green run is checked to confirm `P12` (the binding differential) actually
  ran on every convert fixture, non-vacuously.

## Deliberately stated limits

Honest boundaries, recorded rather than glossed:

1. **Record order is tolerated.** `b4_reverse_order_TOLERATED` passes by design — a
   converted file may legitimately reorder. Documented as a decision, and asserted by a
   probe so it cannot silently become something else.
2. **Comparison is per non-empty field** (`_norm` drops empties on both sides). A field
   empty on both sides is not evidence. Finding 6 is what makes this safe: sparse fixtures
   now exist, so *invention* into an empty field is caught.
3. **`group`/`otpauth` are compared but thinly exercised** — the fixtures leave folder and
   TOTP columns empty, because not all four formats carry them. A defect confined to
   folder mapping alone would not be caught. Named as a real gap.
4. **Mutation runs exclude `chrome_5k.csv`** and lower the settle timeout to 4 s; the
   positive control runs the full corpus at 45 s. `oracle.py` records any exclusion as
   `P0.subset` in its own output, so a reduced run can never read as a full one.
5. **`pass_import` is trusted.** If it and `lib/pwcsv-remap.js` disagree, the oracle wins
   and the page is wrong. That is the point of a differential oracle, and it is also the
   one assumption that cannot be checked from inside.
