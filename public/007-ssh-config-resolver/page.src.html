What this tool is sure about, and what it is not — read this before trusting it

How it knows. The resolver was not written from the man page. It was written against ssh -G — OpenSSH's own resolver — and then diffed against it on 5,493 randomly generated configs across four seeds, with zero mismatches. The diff is a replay: the tool's answer is written back out as a minimal config, run through the real ssh, and every one of the ~80 options it prints must come out identical. That catches a dropped directive and an invented one, not just a wrong value.

Things it deliberately refuses instead of guessing — each one is named on the page when your file uses it, rather than silently mis-answered:

  • Match exec — runs a shell command; a browser cannot.
  • Match canonical / Match final — need OpenSSH's second resolution pass.
  • Include — pulls another file off your disk, which this page cannot read.
  • %h, %p, %r, ~ and friends — shown as written, never expanded. If one appears in a Hostname or User that a later Match depends on, the page says so, because that answer could be wrong.
  • Keywords outside its probed OpenSSH 9.6p1 table are reported as not recognised by this tool — a weaker claim than invalid, and deliberately so.

One real gap worth knowing: OpenSSH derives a few options from others — BatchMode yes silently sets ServerAliveInterval 300. This page reports what your file sets, so a derived value appears in ssh -G and not here. That is the intended difference, not a bug: no line in your file set it.

Verified against OpenSSH_9.6p1. Other versions differ in details; the surprises below have been stable for many releases, but if your ssh is much older or newer, trust ssh -G over this page.

The five rules that trip everyone up (all measured, not remembered)
  • First value wins, not last. The earliest line that sets a keyword is the one that applies — so a Host * block at the top of your file quietly beats every specific block below it.
  • Host is case-sensitive; Match host is not. Host FOO does not match foo. Match host FOO does.
  • Host patterns are separated by spaces; Match host patterns by commas. Host a.ex,b.ex is one pattern with a comma in it and matches neither.
  • Host matches what you typed; Match host matches the current Hostname. A Hostname set earlier changes what a later Match host sees — so moving a block changes the answer.
  • One negation vetoes the whole block, wherever it sits in the list — and a list of only negations (Host !foo) matches nothing at all.
