Before you start. A password export is plaintext — every credential you own, readable. Two habits worth keeping regardless of which tool you use: do this on a machine you trust, and delete the export file (and empty the trash) the moment the import is done. You can verify this page's claim about not uploading anything: open your browser's Network tab, convert a file, and watch that nothing carrying your data leaves.

Anything else is refused, on purpose. If your file is a KeePass, Dashlane, NordPass or Enpass export, this page tells you so and converts nothing. Guessing a column mapping on a password file is the one failure that actually costs you something — a silently mis-mapped export puts your passwords in the notes field of a manager you have not audited yet. Four formats it can be sure about, and a clear no for the rest.

To evaluate this you need to understand

  1. The mapping is the whole product. These exports carry the same data under different column names; nothing is transformed, only renamed and reordered.
  2. CSV is harder than it looks. Passwords contain commas, quotes and newlines. This uses Papa Parse (MIT) rather than splitting on commas, which is where hand-written converters corrupt data.
  3. The column mappings are not guesses. They are transcribed from pass-import, a mature importer, and a test suite checks this page against it row by row.
  4. "In your browser" is checkable, not a promise. There is no upload code here. Your Network tab is the proof, and it costs you ten seconds.
  5. Refusal is the safety property. Four formats supported and everything else declined beats broad support that is sometimes silently wrong.

How it was checked

Every conversion is compared, row by row, against pass-import's own parsers — the page's output is re-parsed and must match the reference exactly, including embedded newlines, quoted commas, unicode and preserved whitespace. The test corpus is 13 files covering CRLF endings, a UTF-8 BOM, an empty file, a header-only file, 5,000 rows, and four unsupported formats that must be refused. The oracle and its own adversarial probe are public: oracles/015-password-csv-remapper. A separate reviewer on a different model re-ran it independently; that verdict is recorded in the repo's ledger rather than summarised here.
