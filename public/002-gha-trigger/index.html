What this models — and what it deliberately does not

Modelled: event presence in on:; branches / branches-ignore / tags / tags-ignore / paths / paths-ignore; types including the pull_request defaults; GitHub's filter-pattern glob rules — * never crosses /, ** does, a leading **/ may match zero segments (so **/README.md matches a root README.md), ? and + are quantifiers on the preceding character (so *.jsx? matches both page.js and page.jsx), character ranges, and \ to escape a literal *, ?, + or [; conjunction across filter categories and disjunction within one; order-dependent ! negation in both include and ignore lists; branch-vs-tag filter exclusivity on push; the fact that path filters are not evaluated for tag pushes; and the config errors GitHub rejects outright (mutually-exclusive keys, and any key other than inputs under workflow_dispatch).

Not modelled (these can still stop a run that this tool says WILL RUN): job- and step-level if: conditions · concurrency cancellation · workflow_call / reusable workflows · runner availability, billing limits and spending caps · required-status or ruleset gating · org/repo policy disabling Actions · [skip ci] in the commit message · and the changed-file edge cases where GitHub gives up on paths filtering — a diff over 3,000 files whose matches fall outside the first 3,000 returned, a push of more than 1,000 commits, or a diff that times out (the last two make the workflow run regardless of the filter).

A "WILL RUN" here means the event filters admit this event — not that the run will succeed.

Why on: is a trap in YAML (and why this parser ignores the spec on purpose)

In YAML 1.1 the bare token on is a boolean — the same family as yes, no, true. A strict YAML 1.1 parser reads the key on: in every Actions workflow as the boolean true, so workflow["on"] is undefined and workflow[true] holds your triggers. GitHub's own parser special-cases this. This tool's parser never coerces scalars to booleans or numbers at all, which sidesteps the trap and keeps on a string. If you write "on": quoted, that works here too.
