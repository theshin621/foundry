gha-trigger — will this workflow run?

Paste a GitHub Actions workflow, describe the event, and see which filter decided it. Everything runs in your browser — nothing is uploaded, no signup, no account.

How it decides

The filter-pattern matcher is a port of nektos/act’s pkg/workflowpattern (MIT), pinned at commit 4f41128. The pattern semantics are that library’s, line for line. The execution is not: act relies on Go’s RE2 engine, which is linear-time, and JavaScript’s RegExp backtracks — so this page compiles each pattern to an NFA and runs a state-set simulation instead. No pattern can trigger catastrophic backtracking: cost is linear in pattern length × input length, never exponential.

Linear is not the same as free, though. That product is still yours to control, so an evaluation stops once it has spent a fixed amount of matching work (about a fifth of a second) and says CANNOT TELL rather than freezing the tab or guessing. The workflow parser refuses documents over 1 MiB or nested deeper than 64 levels, and the event form caps the changed-file list at 5,000 entries. Real workflows are nowhere near any of these.

Verified before publishing: 211,118 (pattern, value) pairs diffed against a real Go/RE2 build of act with zero divergences, plus an independent 56,766-pair differential by a second checker, also zero · GitHub’s own published filter cheat-sheet, 46/46 · act’s own 64-case test corpus, 64/64 · every known catastrophic-backtracking probe under 0.2 ms.

What it models

  • push — branches, branches-ignore, tags, tags-ignore, paths, paths-ignore, and the branch-vs-tag rule (define only tag filters and branch pushes stop matching, and vice versa).
  • pull_request / pull_request_target — types (with GitHub’s default of opened, synchronize, reopened), branches against the base branch, and path filters.
  • workflow_dispatch, schedule — no ref or path filters exist for these, so the answer is about where the file lives, and the page says so.
  • Negated patterns (!pattern) with GitHub’s order-sensitive re-include behaviour.
  • Mutually exclusive pairs (branches + branches-ignore) reported as config errors.

What it does not model — read this before trusting a verdict

  • Job-level if: conditions, concurrency, and matrix expansion. The verdict is about whether the workflow is triggered, not whether a given job ends up running.
  • Whether the workflow file exists on the ref being pushed, repository or org-level Actions policy, required approvals for first-time contributors, and — new since 2026-07-28 — GitHub holding runs it judges potentially malicious. Those can stop a run that this page says will run. GitHub does not document those heuristics, so nothing here guesses at them.
  • Non-ASCII characters in patterns. The matcher compares them byte-wise; GitHub’s behaviour there is undocumented and unverified, so treat such a verdict as unknown rather than authoritative.
  • Reusable workflows (workflow_call) and the remaining ~30 webhook events.
  • Inputs past the limits above. Beyond them the page says CANNOT TELL and names the limit — it will not return a verdict it did not finish computing.
