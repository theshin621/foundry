CODEOWNERS — who actually gets requested?

Paste your CODEOWNERS file and the paths a pull request touches. For every file you get the rule that won, the owners GitHub would request, and the rules that matched but lost — plus the lines GitHub silently skips. Free, no signup, and it never leaves your browser.

How the decision is made. GitHub's rule is one line long and catches almost everyone: “Order is important; the last matching pattern takes the most precedence.” Not the most specific pattern — the last one. A rule with no owners still wins; it just leaves the file unowned, which is how you carve an exception out of a broader rule.

What this cannot know. GitHub also requires each owner to exist and to have write access — “if you specify a user or team that doesn't exist or has insufficient access, a code owner will not be assigned.” This page has no access to your org, so it checks the format of an owner and never its existence. A row here can name an owner GitHub would not actually request.

Where the matching comes from. The pattern semantics are ported line-for-line from hmarr/codeowners (MIT, © 2020 Harry Marr), pinned at commit 11d3ff2659b769bcb43ddef81a6ab19d1205d9c2, and checked against its own test corpus and against a differential harness that re-answers the same pattern/path pairs with the real Go implementation. Two divergences are known and deliberate: a malformed line is skipped here (GitHub's documented behaviour) rather than aborting the whole file, and the pattern / — which crashes the reference implementation — is reported as matching nothing.

Why it can't hang. Patterns are compiled to a non-backtracking automaton, not to a JavaScript RegExp, so no input can trigger catastrophic backtracking. And because linear time still is not bounded time, every stage that costs anything — reading the file, compiling each pattern, matching — is metered against a wall clock: past roughly 750 ms this page tells you it cannot evaluate rather than freezing or answering from a half-finished pass — and that includes drawing the answer, which is a stage that costs time like any other. The table therefore draws at most 1,000 files, 20 owners per rule and 10 losing rules per file, and says so when it reaches any of those; the counts above it are computed over everything you pasted.
